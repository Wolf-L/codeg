# 原生 ACP 会话功能

本社区构建基于官方 Codeg v0.34.0，接入完整增强版 Codex/Claude ACP。能力由每次连接的初始化声明决定；其他适配器继续使用原有标准 ACP 路径。

## 适配器安装

从以下 Release 下载对应平台的独立包，并核对 SHA256：

- https://github.com/Wolf-L/codex-acp/releases/tag/full-enhancements-20261009
- https://github.com/Wolf-L/claude-agent-acp/releases/tag/full-enhancements-20261009-r2

保持整个解压目录。Windows 启动器在包根目录，Linux 在 `bin`。让 Codeg 进程的 PATH 能找到 `codex-acp` 和 `claude-agent-acp`，或使用已全局安装的完整增强版。替换后新建 ACP 连接。设置中的官方更新仍指向上游发行，不会自动安装本社区增强版。账号、服务商配置沿用原设置；便携 ACP 包附带 Node，Git 和系统库仍由系统提供。

## 编辑历史消息

适配器声明同会话回退后，已完成的用户消息显示编辑入口。先结束或停止生成，并处理待发送队列。确认编辑将原生历史回退到选中消息之前，保持会话 ID，刷新历史并把修改后的文本/图片放回输入框，由用户检查后正常发送。不会创建编辑分支，也不会自动发送。当前连接中新发送的消息不需要重新打开会话；确认时会用完整最新历史、精确内容及发送时间解析临时消息，尚未保存或重复匹配会明确拒绝。

请求前会核对选中消息与最新历史，使用原生 ID 和指纹。Codex 从当前有效 rollout 谱系读取原始文本，保留空白。陈旧、歧义或不支持的目标会明确拒绝；重复文本或附件没有可证明的原生消息 ID 时不会猜测定位。响应丢失后应重连并检查历史，不能直接重复修改。

## 编辑时同时恢复文件

Codeg 声明工作目录检查点能力后，编辑窗口默认选择“回退消息并恢复文件”。先预览路径，再确认；程序先恢复文件，再回退原生历史。选择“仅回退消息”则明确保留当前文件。Codeg 在完整执行的主机消息前后捕获普通文件内容，所以非 Git 目录中的命令行写入也能覆盖；快照只保存在本机。

仅已捕获的轮次可恢复。旧消息、取消或失败的轮次、无法证明原始身份的附件、后台或排队任务、捕获不完整时都会拒绝恢复。轮次之间的手动修改、后续文件冲突也会阻止恢复；无关文件保留。捕获上限为 5,000 个文件、10,000 个条目、单文件 8 MiB、总计 64 MiB。所有层级的 `.git`、`node_modules`、`target`、`.next`、`buildcache` 均排除；链接、硬链接、特殊文件和不可读文件导致捕获不完整。工作目录外文件、ACL、时间戳、Git 暂存区/HEAD 和空目录删除不在恢复范围；Unix 文件权限位会捕获并恢复。一次最多回退 256 轮。每个会话的检查点存储上限为 1 GiB；新捕获会在耗尽配额之前停止，保留已有数据。不自动删除，也没有跨会话的全局配额。移走本轮新建文件时，目前要求检查点存储与工作目录位于同一文件系统；跨盘时恢复失败并撤销本次写入。

恢复过程保留本地日志与备份，并非文件系统原子快照。写入失败时尝试撤销本次恢复写入；无法验证时明确报告结果不确定。消息回退成功不代表文件恢复成功，也不能事后为旧消息补造历史检查点。文件恢复后，持久化的恢复状态会阻止重叠工作目录中的新消息，直到对应的历史回退完成。重连恢复时会重新检查实际文件内容。并发写入、取消后尚未确认结束的任务会使检查点覆盖失效。

取消请求后若最终响应丢失，Codeg 会保留写入保护；仅重连不能证明工具已停止，重叠目录中的文件/历史回退会继续被拒绝。内存中的写入保护在重启 Codeg 后重置，因此重启前应确认脱离连接运行的工具已停止；持久化恢复日志不会因重启清除。

## 原生会话工具

- 按实际声明展示上下文、用量、MCP、命令、Agent 和插件；Claude 完整上下文是显式操作，可能请求已配置服务商的 token-count 接口。
- Codex 原生队列支持添加、编辑、删除、重排和启动，由原生程序持久化和派发，与 Codeg 本地输入队列区分。空闲时添加可能立即启动；取消后保留待发项，显式启动继续。当前展示前 100 项，列表不完整时禁用重排；带文本位置注解的条目不做有损编辑。
- Claude 显示原生待发消息 ID，可撤回单条尚未开始的消息。不是持久队列，原生返回 false 不会显示成功。
- 独立的原生文件工具面板继续保留：Claude 使用原生 checkpoint，Codex 在 Git 中撤销单个工具记录的文本补丁。这些控件不回退历史，覆盖范围小于编辑窗口的主机工作目录检查点；先预览再确认，并检查影响路径与跳过结果。
- 可用的刷新、重连、MCP 启停和任务转后台按能力开放。“应用已保存 MCP 配置”使用 Codeg 配置并保留注入的伴生服务，遵循原生 revision 和所有权保护，不开放任意 RPC。
- 原生归档/恢复、搜索、附件元数据和目标控制按动作协商。归档不同于本地隐藏或永久删除；解除归档后需重连以重新打开原生路由。

## 构建与验证

版本标识包含 `+native.acp.20261009`，属于社区预发布，不冒充官方发行或官方签名更新。保留官方更新信任配置；以后安装官方新版可能替换这些增强功能。最终提交、校验值、平台验证和测试限制在 Release 说明中列明。

原生测试使用真实适配器/CLI、隔离目录及本地模拟模型服务，不依赖真实账号或现有用户会话。QEMU ARM64 测试不等于物理 ARM 硬件测试。本构建不宣称复刻了专有 Desktop 的全部界面或云端功能。
